Rollen verhindern zweierlei: dass alle alles können — und dass niemand etwas
kann. In einer Community gibt es fünf davon.

## Die fünf Rollen

| Rolle | Kurz gesagt |
|---|---|
| **Viewer** | Liest die Community und kommentiert mit |
| **Editor** | Verfasst Inhalte — moderiert aber nicht |
| **Moderator** | Moderiert Meldungen, Kommentare und Beiträge — verfasst aber nicht |
| **Admin** | Editor und Moderator zusammen, plus Design und Team |
| **Owner** | Admin, plus Übergabe und Löschung der Community |

Editor und Moderator sind **Geschwister**, keine Stufen: Wer schreibt, muss nicht
moderieren dürfen, und wer moderiert, muss nicht schreiben dürfen. Erst der
Admin vereint beides.

## Wer darf was

| Recht | Viewer | Editor | Moderator | Admin | Owner |
|---|:--:|:--:|:--:|:--:|:--:|
| Dashboard öffnen | ✓ | ✓ | ✓ | ✓ | ✓ |
| Beiträge verfassen | | ✓ | | ✓ | ✓ |
| Seiten bearbeiten | | ✓ | | ✓ | ✓ |
| Medien verwalten | | ✓ | | ✓ | ✓ |
| Events verwalten | | ✓ | | ✓ | ✓ |
| Kommentare moderieren | | | ✓ | ✓ | ✓ |
| Meldungen bearbeiten | | | ✓ | ✓ | ✓ |
| Beiträge moderieren | | | ✓ | ✓ | ✓ |
| Kurse verwalten | | | | ✓ | ✓ |
| Aktivitäten verwalten | | | | ✓ | ✓ |
| Design und Branding | | | | ✓ | ✓ |
| Team verwalten | | | | ✓ | ✓ |
| Community übergeben | | | | | ✓ |
| Community löschen | | | | | ✓ |

::note
Jedes Mitglied hat **genau eine** Rolle pro Community. Wer mehrere Communities
betreut, kann in jeder eine andere Rolle haben.
::

::note
**Rollen sind nicht der einzige Weg zu Rechten.** Wer lange und verlässlich
mitmacht, steigt in den
[Vertrauensstufen](/de/anleitung/produkte/diskussionen) auf und darf dadurch
zusätzlich etwas — private Nachrichten schreiben, später fremde Themen
aufräumen. Eine Stufe **nimmt nie etwas weg**; sie legt nur zu dem, was deine
Rolle ohnehin erlaubt.
::

## Was keine Rolle darf

Abrechnung, Plan und Zahlungsdaten gehören allein dem **Owner**: der Reiter
**Plan** in den Community-Einstellungen erscheint nur für ihn. Admin, Moderator
und Editor verwalten Inhalte und Team — nie den Vertrag. Siehe
[Abrechnung](/de/anleitung/abrechnung).

Ebenso sind instanzweite Dinge (Systemeinstellungen, Nutzerverwaltung über alle
Communities hinweg, Protokolle) dem Plattform-Betrieb vorbehalten und für
Community-Rollen nicht erreichbar.

## Wie jemand Mitglied wird

Deine Community steht unter `deinname.pukalani.app`. Wer sich dort anmeldet,
wird Mitglied — die Anmeldung läuft per Code an die E-Mail-Adresse, ein
Passwort ist nicht nötig.

Die Rolle **Owner** bekommt automatisch, wer die Community anlegt.

## Das Team verwalten

Unter **Dashboard → Community-Einstellungen → Mitglieder** erledigst du alles
selbst — vier Handgriffe:

| Handgriff | Was passiert |
|---|---|
| **Einladen** | E-Mail-Adresse und Rolle eingeben. Der Link gilt **7 Tage**. |
| **Rolle ändern** | Wirkt sofort. Dich selbst kannst du nicht herabstufen. |
| **Zugang entziehen** | Die Person kommt nicht mehr hinein und kann nichts mehr schreiben, auch keine privaten Nachrichten — **Beiträge und Name bleiben stehen**. Zurück geht es nur per neuer Einladung. |
| **Besitz übertragen** | Macht jemand anderen zum Owner. Ein eigener, seltener Vorgang. |

Standardmäßig zeigt die Liste das **Team** (Owner, Admin, Moderator, Editor);
ein Klick zeigt **alle** Mitglieder.

### Was eine entfernte Person sieht

Wer angemeldet ist und dem der Zugang entzogen wurde, sieht in deiner Community
auf jeder Seite nur noch einen **Hinweis**: Ein Administrator dieser Community
hat den Zugang entzogen. Wer das war, steht dort nicht.

Von dieser Seite aus kann die Person der Leitung **eine Nachricht pro Woche**
schreiben. Sie geht per E-Mail an Owner und Admins und erscheint in ihrer
Glocke. Die Person erfährt dabei weder Namen noch Adressen. Ihr seht ihren
Namen und ihre E-Mail-Adresse und könnt direkt auf die E-Mail antworten — oder
es lassen.

Ladet ihr die Person neu ein, kann sie die Einladung auf der Hinweisseite
annehmen und ist sofort wieder dabei.

::note
Ist deine Community **öffentlich**, kann eine entfernte Person abgemeldet
weiterhin lesen, was jeder Besucher liest. Schreiben kann sie nicht.
::

::note
**Die letzte Owner-Rolle lässt sich nicht abgeben.** Eine Community ohne Owner
könnte niemand mehr verwalten — Pukalani verhindert das.
::

## Mitglieder dürfen einladen

Eine Community wächst schneller, wenn nicht nur das Team Menschen dazuholen
kann. Unter **Dashboard → Community → Allgemein** steht dafür der Schalter
**Mitglieder dürfen einladen**.

Ist er an, darf **jedes Mitglied** — auch ein Viewer — Menschen einladen, und
zwar nach klaren Grenzen:

| Regel | Warum |
|---|---|
| **Fünf Einladungen pro Woche** je Mitglied, rollierend | Genug für echte Empfehlungen, zu wenig für Massenversand |
| **Immer als Leser/in** | Rollen zu vergeben bleibt eine Team-Entscheidung — auch wenn jemand versucht, es zu umgehen |
| **Verbraucht ist eine Einladung mit dem Versand**, nicht mit der Annahme | Sonst kosteten 500 nie angenommene Einladungen nichts, und genau die sind der Missbrauchsfall |

Das Formular sagt den Stand: *Noch 3 von 5 Einladungen diese Woche.* Ist das
Kontingent aufgebraucht, steht dort, dass es in ein paar Tagen weitergeht.

::note
**Owner und Admins bleiben unbegrenzt** und vom Schalter unberührt. Er fügt ein
Recht hinzu und nimmt keines weg — wer seine Community nicht mehr besetzen
könnte, weil er den Schalter für seine Mitglieder umgelegt hat, wäre schlechter
dran als vorher. Umlegen darf ihn nur, wer das Team verwaltet: Wer einladen
darf, darf das Einladen nicht abschalten.
::

Wessen Einladung angenommen wird, bekommt das Abzeichen **Promoter** — und wenn
die Eingeladenen später in den
[Vertrauensstufen](/de/anleitung/produkte/diskussionen) aufsteigen, kommen
**Campaigner** und **Champion** dazu.

## Was du beim Verteilen beachten solltest

- **Sparsam anfangen.** Es ist leichter, Rechte zu geben als sie wieder
  zurückzunehmen.
- **Moderator statt Admin**, wenn jemand nur aufräumen soll — er kommt dann
  gar nicht erst an Design oder Team.
- **Owner bleibt bei dir.** Übergeben ist absichtlich ein eigener, seltener
  Vorgang.
